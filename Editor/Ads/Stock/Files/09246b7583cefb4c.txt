# Metica Integration Guide

This guide covers all supported Metica integration scenarios in the GDMonetization SDK.

---

## Configuration

Metica integration is controlled by two settings in different ScriptableObjects.

| Setting | Asset | Description |
|---|---|---|
| `UseMetica` | `RemoteConfiguration` | Metica handles ad serving and Smart Floors via MAX mediation — toggled at runtime |
| `UseMeticaForAnalytics` | `SDKConfiguration` | Metica receives genre analytics events — build-time flag, also drives `METICA_ANALYTICS` symbol |

These two settings can be combined freely to support all 4 scenarios below.

---

## Scenario Quick Reference

| Scenario | RemoteConfig.UseMetica | SDKConfig.UseMeticaForAnalytics | Description |
|---|---|---|---|
| 1 | `true` | `false` | Ads only — Smart Floors via MAX mediation |
| 2 | `false` | `true` | Analytics only — genre events |
| 3 | `true` | `true` | Both ads and analytics (single SDK instance) |
| 4 | `false` | `false` | No Metica — AppLovin MAX + AdMob fallback |

---

## Scenario 1 — Metica for Ads Only

**Settings:**
```
RemoteConfiguration.UseMetica        = true
SDKConfiguration.UseMeticaForAnalytics = false
```

### What Happens Internally

- `AdsManager` initializes `AdNetworkMetica` with your MAX SDK key
- Metica SDK initializes with `SystemInfo.deviceUniqueIdentifier` as userId and MAX mediation info
- Smart Floors result is fetched — device is assigned to `Trial` or `Holdout` group
- Adjust initializes independently — no dependency on Metica completing first (both use the same pre-generated userId)

### Accessing the User Group at Runtime

```csharp
string group = AdNetworkMetica.GetUserGroup;
// Returns: "Trial", "Holdout", or "Initializing"
```

> **Note:** No additional code is needed. Metica handles ad loading, floor prices, and waterfall configuration automatically through MAX.

---

## Scenario 2 — Metica for Analytics Only

**Settings:**
```
RemoteConfiguration.UseMetica        = false
SDKConfiguration.UseMeticaForAnalytics = true
```

### What Happens Internally

- `MeticaSdk.InitializeAnalytics()` is called synchronously at `BeforeSceneLoad` — before the consent panel, before any other SDK
- The Metica event queue is active immediately, so any events fired before consent completes are buffered and delivered once the SDK is fully ready
- Adjust initializes independently post-consent — no dependency on Metica (both use the same pre-generated userId)
- Genre analytics are registered and ready to send events

> **Note:** When `UseMeticaForAnalytics = true`, the GDMonetization SDK automatically adds the `METICA_ANALYTICS` scripting define symbol for Android and iOS via `MeticaDefineSymbolManager`. This symbol gates `MeticaSdk.Analytics` at compile time — without it the API does not exist. You do **not** need to add it manually; changing `UseMeticaForAnalytics` in the Inspector syncs it immediately.

---

### Step 1 — Create and Assign Your Genre SO

There are no pre-built genre assets. Use the **Genre Creator** to generate a genre tailored to your game's events (see [Creating a Genre](#creating-a-genre)).

Once created, click **Apply Genre SO to SDKConfiguration** in the Genre Creator window — it assigns the SO automatically. To assign manually:

1. Open `Resources/Configurations/SDKConfiguration` in the Unity Inspector
2. Drag your `{Genre}AnalyticsSO` asset from `Resources/Configurations/Game Genres/` into the **Genre SO** field

Only this SO is initialized at runtime.

### Step 2 — Send Events in Your Game Code

Each generated event data class has **required** and **optional** fields, plus a `CustomFields` escape hatch.

- **Required fields** are constructor parameters — the compiler enforces them.
- **Optional fields** are set via object initializer. If omitted, they are **silently excluded from the payload** — never sent as default zeros or empty strings.
- **`CustomFields`** — `Dictionary<string, object>` on every data class for ad-hoc fields without touching the generated class.

The examples below use a `Racing` genre generated by the Genre Creator. Replace the type names with whatever your genre produces.

#### Required only (minimum valid call)

```csharp
AnalyticsManager.Game<IRacingAnalytics>().LevelStarted(
    new RacingLevelStarted(level: 1)
);
```

#### Required + optionals inline

```csharp
AnalyticsManager.Game<IRacingAnalytics>().LevelStarted(
    new RacingLevelStarted(level: 1)
    {
        LevelType = "circuit",
        TrackName = "Monaco"
    }
);
```

#### Build step by step + custom fields

```csharp
var data = new RacingLevelFinished(
    level:       currentLevel,
    levelStatus: playerWon ? "win" : "fail",
    playTime:    Time.time - levelStartTime
);

// Optional fields
data.LapCount    = lapCount;
data.BestLapTime = bestLapTime;

// Ad-hoc fields that aren't in the generated class
data.CustomFields = new Dictionary<string, object>
{
    { "car_model",    selectedCar  },
    { "boost_used",   boostCount   }
};

AnalyticsManager.Game<IRacingAnalytics>().LevelFinished(data);
```

> **Compile-time safety:** Skipping a required constructor parameter is a compile error. Optional fields that are never set are never sent — no accidental zeros or empty strings in your Metica data.

### Genre Interface Naming

All genres are created with the Genre Creator tool. For a genre named `Racing`, the generated types are:

| Type | Name |
|---|---|
| Interface | `IRacingAnalytics` |
| SO asset | `RacingAnalyticsSO` |
| Data classes | `RacingLevelStarted`, `RacingLevelFinished`, … |

Pass the interface to `AnalyticsManager.Game<T>()` to get the analytics instance.

### A/B Test Fields

Every genre analytics instance supports optional A/B test metadata. When set, the fields are automatically included in all Metica event payloads — no changes needed per event.

```csharp
var analytics = AnalyticsManager.Game<IPuzzleSuccessFailAnalytics>();

if (analytics != null)
{
    analytics.AbTest          = "price_test_q2";
    analytics.AbGroup         = "control";
    analytics.AbTestStartDate = "2026-06-01";
}
```

Fields are omitted from the payload when `null` or empty. Set them back to `null` to stop sending. See [`docs/ab-test-fields.md`](../../../docs/ab-test-fields.md) for full reference.

### Sending Events Without a Genre

If you don't want to create a genre but still want to send a custom event to Metica (and Firebase/AppMetrica simultaneously), use `AnalyticsManager.SendEvent` with your own dictionary.

```csharp
AnalyticsManager.SendEvent("levelFinished", new Dictionary<string, object>
{
    { "levelId",      5      },
    { "levelStatus",  "win"  },
    { "playTime",     47.3f  },
    { "attemptCount", 2      }
});
```

> **Important — Metica requires camelCase event names.**
> Firebase and AppMetrica are flexible on naming, but Metica will reject or mis-route events with PascalCase, snake_case, or spaces. Always use `camelCase` for the event name when Metica analytics is enabled.

| Format | Example | Metica |
|---|---|---|
| `camelCase` | `levelFinished` | ✅ Accepted |
| `PascalCase` | `LevelFinished` | ❌ Rejected |
| `snake_case` | `level_finished` | ❌ Rejected |

This routes the event to **all enabled networks at once** — AppMetrica, Firebase, and Metica. No genre setup needed.

### Creating a Genre

Use the built-in **Genre Creator** tool to generate all required files and assets — either manually or by importing an Excel event schema.

#### Step 1 — Open the Genre Creator

In the Unity menu bar:

```
GameDistrict → Monetization → Metica Analytics → Create New Genre...
```

#### Step 2 — Configure the Genre

**Option A — Manual**

In the **Manual** tab:

| Field | Description |
|---|---|
| **Name** | PascalCase genre name, e.g. `Racing` |
| **Events** | One row per event your genre fires |
| **Fields** | Per-event data fields — name and type (`string`, `int`, `float`, `bool`) |

Two starter events (`LevelStarted` / `LevelFinished`) are pre-filled. Remove, rename, or add events and fields to match your game.

**Option B — Import from Excel**

Switch to the **Import from Excel** tab, browse to an `.xlsx` event schema file, select the sheet, and click **Import & Preview**. The parser reads the `parameter` column (with the column to its left as the event name, or a `metica event name` header). Base SDK parameters (`adid`, `appToken`, `abTest`, etc.) and core Metica events are filtered out automatically. Review the imported events in the preview, then proceed.

#### Step 3 — Click "Create Genre Files"

The tool generates four C# files under `Runtime/Scripts/Analytics/Genres/{Genre}/`:

| File | Purpose |
|---|---|
| `I{Genre}Analytics.cs` | Interface — one method per event |
| `{Genre}Data.cs` | Data classes — one plain class per event |
| `{Genre}Analytics.cs` | Implementation — builds payloads and calls `LogCustomEvent` |
| `{Genre}AnalyticsSO.cs` | ScriptableObject wrapper — registered with `SDKConfiguration` |

Unity then recompiles.

#### Step 4 — Wait for Recompile (automatic)

After Unity finishes recompiling, the tool automatically:

- Creates `{Genre}Analytics.asset` in `Resources/Configurations/Game Genres/`
- Creates `{Genre}AnalyticsSO.asset` in the same folder
- Wires the analytics asset into the SO asset
- Shows a confirmation dialog

No manual asset creation needed.

#### Step 5 — Apply to SDKConfiguration

Back in the Genre Creator window, click:

```
Apply Genre SO to SDKConfiguration
```

A confirmation dialog shows the current and new genre SO. Confirm to assign. The Inspector opens on `SDKConfiguration` so you can verify.

#### Step 6 — Send Events in Your Game Code

Use the generated interface via `AnalyticsManager.Game<T>()`. For a `Racing` genre with a `RaceFinished` event:

```csharp
AnalyticsManager.Game<IRacingAnalytics>().RaceFinished(
    new RacingRaceFinished
    {
        Level       = 3,
        LevelType   = "circuit",
        LevelStatus = "win",
        PlayTime    = 87.4f,
    }
);
```

The data class name follows the pattern `{Genre}{EventName}` (e.g. `RacingRaceFinished`). Field names in code are PascalCase. The analytics payload key for each field is **not** transformed — for manual genres it is the field name exactly as typed; for Excel imports it is the raw cell value from the `parameter` column.

## Scenario 3 — Metica for Both Ads and Analytics

**Settings:**
```
RemoteConfiguration.UseMetica        = true
SDKConfiguration.UseMeticaForAnalytics = true
```

### What Happens Internally

- `MeticaSdk.InitializeAnalytics()` is called synchronously at `BeforeSceneLoad` — analytics and its event queue are active immediately
- Post-consent, `AdNetworkMetica` calls `MeticaSdk.InitializeAsync(config, mediationInfo)` which upgrades the already-initialized analytics SDK to full ads+analytics mode
- Adjust initializes independently — no dependency on Metica completing first
- Genre analytics are registered and ready to send events

> Both ad serving and genre events work simultaneously with a single Metica SDK instance. Early-session events fired before consent are buffered and delivered once the ads upgrade completes.

### Accessing Smart Floors User Group

```csharp
string group = AdNetworkMetica.GetUserGroup; // "Trial" or "Holdout"
```

### Sending Genre Analytics Events

Assign your genre SO in `SDKConfiguration` (same as Scenario 2 Step 1), then send events normally using your wizard-generated interface:

```csharp
AnalyticsManager.Game<IRacingAnalytics>().LevelStarted(
    new RacingLevelStarted(level: 1) { LevelType = "circuit" }
);
```

---

## Scenario 4 — Not Using Metica

**Settings:**
```
RemoteConfiguration.UseMetica        = false
SDKConfiguration.UseMeticaForAnalytics = false
```

### What Happens Internally

- Metica SDK is never initialized
- `AdNetworkMetica` is excluded from the ad network chain — AppLovin MAX is used instead (`RemoteConfiguration.UseMetica = false`)
- Adjust initializes immediately (no Metica dependency)
- Genre analytics ScriptableObjects are still loaded but no Metica events are sent

> Ads still work through the AppLovin MAX + AdMob fallback chain. No code changes are needed in your game.

### Ad Calls Work Regardless of Metica Settings

```csharp
AdsManager.ShowInterstitial("level_complete", () => {
    // on ad closed
});

AdsManager.ShowRewarded("extra_lives", () => {
    // on reward granted
});
```

> **Warning:** If `UseMeticaForAnalytics = false`, calls to `AnalyticsManager.Game<T>()` will still compile and run — events will silently not be sent to Metica. Ensure you are not expecting Metica events in your dashboard in this mode.

## Initialization Flow Summary

### Current Flow (GDMonetization v6.1 / Metica SDK 2.4.0)

Metica 2.4.0 separates analytics and ads initialization into two distinct calls. Analytics initializes synchronously at app boot; ads upgrade happens post-consent. This enables early event buffering before the consent panel is shown.

```
App Launch
    │
    ├── AnalyticsManager.Create()        [BeforeSceneLoad]
    │       ├── All networks read from SDKConfiguration.AnalyticsNetworks
    │       │   and registered into their respective lists
    │       │   (Adjust included — no special handling)
    │       │
    │       └── [if UseMeticaForAnalytics=true]
    │               ├── MeticaInitializer.InitializeAnalytics()
    │               │       └── MeticaSdk.InitializeAnalytics()   ← synchronous, event queue active immediately
    │               └── InitializeAllGenresInternal()             ← registers genre SO, no Metica SDK call
    │
    └── OnAccepted() → ConsentManager   [AfterSceneLoad + privacy policy]
             │
             ├── AnalyticsManager.Initialize()
             │       └── All networks Initialize() in sequence
             │               ├── Firebase.Initialize()
             │               ├── AppMetrica.Initialize()
             │               ├── AdjustNetworkSO.Initialize()          ← stores AppToken + AdId as static properties,
             │               │                                            uses pre-generated userId, no Metica dependency
             │               └── MeticaAnalyticsNetwork.Initialize()   ← no-op (reads Adjust data at event-send time)
             │
             └── AdsManager.Initialize()
                     └── [if RemoteConfiguration.UseMetica=true] → AdNetworkMetica.InitializeAsync(MAX_KEY)
                                                         └── MeticaInitializer.StartInitialize(mediationInfo)
                                                                 └── MeticaSdk.InitializeAsync()   ← upgrades analytics → ads+analytics

Adjust Data Access (pull-based):
    AdjustAnalyticsNetwork.AppToken   ← set once during Adjust init, read by anyone at any time
    AdjustAnalyticsNetwork.AdId       ← set when Adjust SDK provides it, read by anyone at any time
    │
    ├── MeticaAnalyticsNetwork.SendEvent()   ← reads AppToken + AdId at send time
    └── GDMeticaAnalytics.WithBaseFields()   ← reads AppToken + AdId at send time
```

---

### Previous Flow (GDMonetization v6.0 / Metica SDK pre-2.4.0)

In the old flow, a single `MeticaSdk.InitializeAsync` call handled both analytics and ads. Analytics initialization was deferred to post-consent alongside all other networks, meaning early-session events fired before consent were lost.

```
App Launch
    │
    ├── AnalyticsManager.Create()        [BeforeSceneLoad]
    │       └── All networks read from SDKConfiguration.AnalyticsNetworks
    │           and registered into their respective lists
    │
    └── OnAccepted() → ConsentManager   [AfterSceneLoad + privacy policy]
             │
             ├── AnalyticsManager.Initialize()
             │       ├── All networks Initialize() in sequence
             │       │       ├── Firebase.Initialize()
             │       │       ├── AppMetrica.Initialize()
             │       │       ├── AdjustNetworkSO.Initialize()
             │       │       └── MeticaAnalyticsNetwork.Initialize()
             │       │               ├── RemoteConfiguration.UseMetica=true  → skip (ads will init Metica with mediationInfo)
             │       │               └── RemoteConfiguration.UseMetica=false → MeticaInitializer.StartInitialize()
             │       │                                               └── MeticaSdk.InitializeAsync(config, null)
             │       │
             │       └── [if UseMeticaForAnalytics=true]
             │               ├── InitializeAllGenresInternal()
             │               └── Adjust.GetAdid()
             │
             └── AdsManager.Initialize()
                     └── [if RemoteConfiguration.UseMetica=true] → AdNetworkMetica.InitializeAsync(MAX_KEY)
                                                         └── MeticaInitializer.StartInitialize(mediationInfo)
                                                                 └── MeticaSdk.InitializeAsync(config, mediationInfo)
```

> **Key difference:** In v6.0, `MeticaAnalyticsNetwork.Initialize()` was responsible for triggering Metica SDK init in analytics-only mode and each consumer independently loaded Adjust config and registered `GetAdid` callbacks. In v6.1, analytics init moved to `AnalyticsManager.Create()`, and Adjust data is centralized in `AdjustAnalyticsNetwork` as static properties — consumers read `AppToken` and `AdId` at event-send time (pull-based), eliminating callback timing issues.

---

> **Key point (both versions):** Adjust and genre analytics initialization have no ordering dependency on Metica. The userId (`SystemInfo.deviceUniqueIdentifier`) is generated once at class load time and shared with both Metica and Adjust. `AdjustAnalyticsNetwork` is the single source of truth for Adjust data (`AppToken`, `AdId`) — all consumers (genres, Metica network) read these static properties at event-send time rather than storing local copies.

## Standalone Metica Integration (Without GDMonetization SDK)

This section is for developers who want to integrate Metica analytics directly, without using the GDMonetization SDK at all. You will manage SDK installation, initialization, Adjust linking, and event logging yourself.

### Prerequisites

- Your Metica **API Key** and **App ID** — available from the Metica dashboard
- Your Adjust **App Token**
- A MAX SDK Key (obtainable from the AppLovin platform) — _only required if using Metica Ads_

---

### Installation

#### Step A — Install the Metica Core SDK

- Download the `.unitypackage` from the Metica GitHub repository
- In Unity Editor, navigate to `Assets → Import Package → Custom Package`
- Select the downloaded `.unitypackage` and import

#### Step B — Install the Analytics Abstractions Package

The Analytics API requires a separate abstractions package in addition to the core SDK:

- Download `com.metica.analytics.abstractions-1.0.0.tgz` from the Metica repository
- Open Unity Editor and go to `Window → Package Manager`
- Click the **+** button in the top-left corner
- Select `Add package from tarball...`
- Select `com.metica.analytics.abstractions-1.0.0.tgz` and click **Open**

#### Step C — Add the `METICA_ANALYTICS` Scripting Define Symbol

The Metica Analytics API is gated behind a scripting define symbol. Without it, `MeticaSdk.Analytics` will **not** be available at compile time. You must add this manually when integrating without the GDMonetization SDK.

1. In Unity Editor, go to `Edit → Project Settings → Player`
2. Select your target platform (Android / iOS)
3. Find the **Scripting Define Symbols** field under **Other Settings**
4. Add `METICA_ANALYTICS` and click **Apply**

This is what the symbol enables inside the Metica SDK itself:

```csharp
#if METICA_ANALYTICS
    public static IMeticaAnalytics Analytics { get; } = new MeticaAnalyticsImpl(PlatformDelegate);
#endif
```

> **Warning:** If `METICA_ANALYTICS` is not defined, `MeticaSdk.Analytics` will not exist and your code will fail to compile. This symbol must be present on every platform you ship to.

---

### Step 1 — Choose a User ID

Metica requires a stable user identifier. Use `SystemInfo.deviceUniqueIdentifier` as a reliable device-level ID that stays consistent across sessions.

```csharp
string userId = SystemInfo.deviceUniqueIdentifier;
```

> **Note:** Pass this same ID to Adjust as `ExternalDeviceId` so both systems reference the same user. The `userId` parameter is optional in Metica — if omitted, Metica auto-generates a UUID. However, providing your own ensures consistent cross-platform attribution.

---

### Step 2 — Initialize Metica SDK

Metica SDK 2.4.0 supports two initialization flows. Choose the one that fits your boot sequence.

#### Single-call initialization (standard)

Call `MeticaSdk.InitializeAsync` after consent. Analytics and ads (if using them) initialize together. Any events fired before this call completes are lost — use two-stage if early events matter.

```csharp
using Metica;
using Metica.Analytics.Abstractions;
using System.Threading.Tasks;

async Task InitializeMetica()
{
    string userId = SystemInfo.deviceUniqueIdentifier;

    MeticaSdk.SetLogEnabled(true); // disable in production builds

    var config = new MeticaInitConfig(
        apiKey: "YOUR_METICA_API_KEY",
        appId:  "YOUR_METICA_APP_ID",
        userId: userId
    );

    // mediationInfo: null = analytics-only, no ads
    MeticaInitResponse response = await MeticaSdk.InitializeAsync(config, mediationInfo: null);
    Debug.Log($"Metica initialized. UserId: {response.UserId}");

    IMeticaAnalytics analytics = MeticaSdk.Analytics;
}
```

#### Two-stage initialization (early analytics)

Call `MeticaSdk.InitializeAnalytics` at app start — before consent, before any loading screen. The event queue activates immediately so early-session events (install, sessionStart) are buffered and delivered. Later, call `InitializeAsync` with mediation info to add ads on top.

```csharp
// Stage 1 — at app start (BeforeSceneLoad or Awake), before consent
var config = new MeticaInitConfig("YOUR_API_KEY", "YOUR_APP_ID", SystemInfo.deviceUniqueIdentifier);
MeticaSdk.InitializeAnalytics(config);   // synchronous, returns immediately

// ... early-session events can be fired here and will be buffered ...

// Stage 2 — after consent, when ads are needed
var mediationInfo = new MeticaMediationInfo(MeticaMediationInfo.MeticaMediationType.MAX, "YOUR_MAX_KEY");
MeticaInitResponse response = await MeticaSdk.InitializeAsync(config, mediationInfo);
```

> Both calls must use the same `MeticaInitConfig` (same ApiKey, AppId, UserId). If the second call supplies a different config, the native SDK keeps the first one and logs a warning.

#### With Metica Ads via MAX mediation (single-call)

```csharp
using Metica;
using Metica.Ads;
using Metica.Analytics.Abstractions;
using System.Threading.Tasks;

async Task InitializeMetica(string maxSdkKey)
{
    string userId = SystemInfo.deviceUniqueIdentifier;

    MeticaSdk.SetLogEnabled(true);

    var config        = new MeticaInitConfig("YOUR_API_KEY", "YOUR_APP_ID", userId);
    var mediationInfo = new MeticaMediationInfo(
        MeticaMediationInfo.MeticaMediationType.MAX,
        maxSdkKey
    );

    MeticaInitResponse response = await MeticaSdk.InitializeAsync(config, mediationInfo);

    // Smart Floors result — Trial or Holdout group
    if (response.SmartFloors.IsSuccess)
    {
        string group = response.SmartFloors.UserGroup == MeticaUserGroup.TRIAL
            ? "Trial" : "Holdout";
        Debug.Log($"Smart Floors group: {group}");
    }
}
```

### Step 3 — Initialize Adjust

Pass the same userId you gave to Metica as `ExternalDeviceId`. This links the same user across both platforms for attribution and revenue reporting. Since the userId is generated before either SDK initializes, there is no ordering dependency — Adjust and Metica can initialize in any order or in parallel.

```csharp
using AdjustSdk;

void InitializeAdjust(string userId)
{
    AdjustConfig adjustConfig = new AdjustConfig(
        "YOUR_ADJUST_APP_TOKEN",
        AdjustEnvironment.Production
    );

    // Link to Metica userId for cross-platform attribution
    adjustConfig.ExternalDeviceId = userId;

    // Attach as a session-level callback parameter for all events
    Adjust.AddGlobalCallbackParameter("user_id", userId);

    Adjust.InitSdk(adjustConfig);
}
```

**Full combined startup sequence:**

```csharp
async Task StartupAsync()
{
    string userId = SystemInfo.deviceUniqueIdentifier;

    // Metica and Adjust can initialize in parallel — both receive the same userId
    var meticaTask = MeticaSdk.InitializeAsync(
        new MeticaInitConfig("YOUR_API_KEY", "YOUR_APP_ID", userId),
        mediationInfo: null
    );

    InitializeAdjust(userId);

    await meticaTask;

    // Optionally retrieve the Adjust adid for cross-referencing in custom events
    Adjust.GetAdid(adid => {
        Debug.Log($"Adjust adid: {adid}");
    });
}
```

### Data Constraints

**Property limits:**
- `customPayload` and user attributes can contain up to **100 properties** each
- Arrays can contain up to **100 elements** of the same primitive type
- Nested objects are **not permitted** — flatten your data into top-level properties

**Allowed value types:**

| Type | Example |
|---|---|
| `string` | `"hello"` |
| `number` | `42`, `3.14` |
| `boolean` | `true`, `false` |
| `array` | `[1, 2, 3]`, `["a", "b"]` |

**Property type consistency:**

Once a property is sent with a specific type, that type is **locked permanently** across all events and all games in your organization. Sending the same property key with a different type later will cause ingestion errors.

```csharp
// First event locks "score" as a number
analytics.LogCustomEvent("levelComplete", new Dictionary<string, object>
{
    ["score"] = 100   // number — locked from this point forward
});

// Sending ["score"] = "100" (string) in any future event will cause errors
```

> **Warning:** If you need to change a property type, stop sending the old property and create a new one with a different name. Violating type consistency causes silent data loss in the ingestion pipeline.

### Step 4 — Log Analytics Events

All Metica analytics calls go through `MeticaSdk.Analytics`. Access it after initialization via the `IMeticaAnalytics` interface:

```csharp
IMeticaAnalytics analytics = MeticaSdk.Analytics;
```

#### Session and lifecycle events

```csharp
// Log when the player starts a new session
analytics.LogSessionStartEvent(customPayload: null);

// Log on first install only
analytics.LogInstallEvent(customPayload: null);
```

#### Ad impression event

```csharp
analytics.LogImpressionEvent(
    value:     0.00555,       // eCPM in USD
    type:      "Rewarded",
    mediator:  "AppLovin",
    source:    "ironSource",
    placement: "LevelSuccess",
    customPayload: null
);
```

#### Purchase event

```csharp
analytics.LogPurchaseEvent(
    productId:   "com.game.gems_100",
    currency:    "USD",
    amount:      4.99,
    status:      "completed",
    errorCode:   null,
    referenceId: "txn_abc123",
    customPayload: null
);
```

#### User state update

```csharp
// Full snapshot — replaces all previously known user attributes
analytics.LogFullStateUpdateEvent(new Dictionary<string, object>
{
    { "playerLevel", 25    },
    { "totalCoins",  15000 },
    { "isPremium",   true  },
    { "country",     "US"  }
});

// Partial update — only updates the specified attributes
analytics.LogPartialStateUpdateEvent(new Dictionary<string, object>
{
    { "totalCoins", 16500 }
});
```

#### Custom event

```csharp
// Event name must be camelCase
analytics.LogCustomEvent(
    eventName: "puzzleLevelEndOfferImpression",
    properties: new Dictionary<string, object>
    {
        ["genre"]          = "puzzle",
        ["levelIndex"]     = 42,
        ["stars"]          = 3,
        ["remainingMoves"] = 5,
        ["cohort"]         = "experiment_a",
    }
);
```

> **Warning:** The following names are reserved and cannot be used with `LogCustomEvent`: `purchase`, `impression`, `sessionStart`, `install`, `fullStateUpdate`, `partialStateUpdate`. Use the dedicated methods above for those event types.

### Step 5 — Dispatch Events

Metica queues events locally and dispatches them in batches. To force an immediate flush — for example, before the app goes to background:

```csharp
MeticaSdk.Events.RequestDispatchEvents();
```

### Complete Standalone Example

```csharp
using System.Collections.Generic;
using System.Threading.Tasks;
using Metica;
using Metica.Analytics.Abstractions;
using AdjustSdk;
using UnityEngine;

public class MeticaStandaloneIntegration : MonoBehaviour
{
    private IMeticaAnalytics _analytics;

    async void Start()
    {
        await InitializeAsync();
    }

    async Task InitializeAsync()
    {
        string userId = SystemInfo.deviceUniqueIdentifier;

        // Metica and Adjust can initialize in parallel — userId is pre-generated
        MeticaSdk.SetLogEnabled(Debug.isDebugBuild);
        var config    = new MeticaInitConfig("YOUR_API_KEY", "YOUR_APP_ID", userId);
        var meticaTask = MeticaSdk.InitializeAsync(config, mediationInfo: null);

        // Adjust does not need to wait for Metica
        AdjustConfig adjustConfig = new AdjustConfig(
            "YOUR_ADJUST_TOKEN", AdjustEnvironment.Production)
        {
            ExternalDeviceId = userId
        };
        Adjust.AddGlobalCallbackParameter("user_id", userId);
        Adjust.InitSdk(adjustConfig);

        var response = await meticaTask;
        Debug.Log($"Metica ready. UserId: {response.UserId}");

        _analytics = MeticaSdk.Analytics;

        // Log install event (only on first launch)
        if (!PlayerPrefs.HasKey("metica_install_logged"))
        {
            _analytics.LogInstallEvent(null);
            PlayerPrefs.SetInt("metica_install_logged", 1);
        }

        // Log session start
        _analytics.LogSessionStartEvent(null);

        // Send initial user state snapshot
        _analytics.LogFullStateUpdateEvent(new Dictionary<string, object>
        {
            { "playerLevel", PlayerPrefs.GetInt("current_level", 1)      },
            { "isPremium",   PlayerPrefs.GetInt("has_purchased", 0) == 1 }
        });
    }

    void OnApplicationPause(bool paused)
    {
        if (paused)
            MeticaSdk.Events.RequestDispatchEvents();
    }
}
```
